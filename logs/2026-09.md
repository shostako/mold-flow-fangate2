## 2026-09-15 実機のスクリュー条件から射出率・充填時間を算出（Issue #7、v0.4.0〜v0.4.1）

sim Issue #88 / PR #89・#90（v0.42.3）の横展開。fangate #16 と同時進行で PR #8 をマージ、タグ v0.4.1。設計と写像の詳細は sim 側の 2026-09-15 のログにある。ここには本リポ固有の判断だけ残す。

### 移植は機械的に当てた

`core/solver.py` は sim との差分 33 行（docstring と表示用フィールドのみ）、`core/two_phase.py` は完全一致、射出条件の UI ブロックも同一。fangate と同じ移植スクリプト（全アンカーを assert 付きで置換）を引数違いで流した。

### 計量位置だけが repo 固有

機械は sim と同じ（φ50 / V/P 18 mm / 3 段・全段 200 mm/s）。既定形状のキャビティは **219.40 cm³** で、φ50 では 111.7 mm のストロークが要る。sim の計量位置 30 mm（理論射出量 23.6 cm³）では既定画面に外挿警告が出続けるので、キャビティを覆う最小ストロークに 15% の余裕を足して 10 mm 丸めた **150 mm** を置いた。実機の設定値ではなく既定形状からの逆算値で、CHANGELOG・CLAUDE.md・`app.py` のコメントに明記。実機値が分かったら `app.py` の `DEF_METERING_POSITION_MM` と `tests/test_injection_ui.py` の `DEF_METER` の 2 箇所を直す。

切替位置は sim の 28/22（30→18 のストローク向け）を持ち込まず `DEF_SWITCH_POSITIONS_MM = ()` で等分割。全段同速なので結果には一切効かない。

### Codex が本リポの PR で捕まえた 2 件

どちらも共有コードなので 3 リポに効き、sim v0.42.3 として本流に戻した。

- **二相の外挿フラグが過剰だった。** 計量がストローク内でも開きキャビティが超えていれば立てていた。`T_open_total` も写像を通るが、それは射出相の到着時刻場の**正規化係数**としてで、そこでは約分される（`t_prof(cum)/t_prof(total)·T_fill` で `T_fill = t_prof(total)` なので出てくるのは `t_prof(cum)` そのもの）。しかも計量より先のセルは `T_inj` 以降に着くのでプールからも露光の時計からも外れる。**外挿値は報告に一切乗らない**のに「射出時間は外挿です」と警告していた。判定を `V_shot` だけにした。
- **メイン結果ペインの外挿警告が最終キャビティ体積としか比べていなかった。** `solve()` の `cell_volume_final` は `_open_thickness_field()` 由来なので、ICM ON では写像が読むのは**開いた隙間**の体積。ストロークが最終形状を覆っていても V/P より先を読む帯がある。

この 2 件は対になった欠陥で、**同じ警告が「出るべきでない所で出て、出るべき所で出ていなかった」**。UI 側で体積を比べ直す設計そのものが間違いだったので、判定を `solve()` の metadata（`injection_extrapolated_past_vp` / `injection_swept_volume_cm3`）に移して二相側と置き場所を揃えた。
